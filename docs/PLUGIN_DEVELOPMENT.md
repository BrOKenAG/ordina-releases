# ordina 插件开发与交付规范

版本：1.0 | 平台：macOS | 目标：ordina 1.10.0 及后续兼容版本。本文同时包含开发目标；实际支持以 `PLUGIN_PROTOCOL.md` 和源码为准。

## 1. 产品原则
插件独立开发、版本、发布和更新；符合已支持协议的新插件无需修改客户端。开发者上传标准 ZIP，用户通过统一插件中心安装、更新、卸载。不得为单个插件硬编码安装逻辑。新增能力须先扩展通用协议。

## 2. 身份与兼容
每个插件提供稳定唯一 ID、名称、简介、图标、独立 SemVer、最低客户端及系统版本、处理器架构、依赖与更新说明。架构迁移保留 ID；已发布同版本资产不可覆盖。实际字段见 PLUGIN_PROTOCOL.md 及代码。

## 3. 工程与交付
推荐独立源码仓库，包含 README、src、resources、tests、scripts（构建与打包）、dist。最终 ZIP 只包含运行所需文件及协议规定的 Manifest，不包含无关源码工程、Git 历史、测试、开发配置或凭据。运行所需 Python/JS 源码可以交付。原生 App 交付编译产物。公开发布仓库仅存必要清单与安装资产。

构建和打包应可重复执行；发布前使用官方发布工具校验。不得自行发明协议字段。依赖随包交付或使用明确验证的兼容环境，不要求普通用户安装 Homebrew、pip 或执行终端命令，不硬编码开发机路径。

## 4. 界面与运行
优先 SwiftUI/AppKit 原生控件，简洁紫色强调、适配深浅色、清晰层级和留白；优先固定布局，必要时滚动，不增加无意义窗口。耗时操作提供状态，不阻塞主线程。Resolve 插件保留既有启动入口。系统或浏览器强制授权须明确引导，不绕过安全机制。

## 5. 生命周期
- 安装：检查兼容性、依赖、空间、签名和摘要；仅写入声明且授权的路径；不得覆盖其他插件；失败不得留下不完整组件。
- 更新：保持 ID，保留配置、项目及历史；自动迁移旧组件，不要求先卸载；多组件版本一致，失败可恢复旧版本；数据迁移须可恢复。
- 卸载：仅移除本插件拥有的组件及注册项，默认保留用户数据，彻底清除需单独确认。
- 下架：普通目录不再提供新安装或正常更新；已安装插件可继续使用及卸载。旧客户端、离线缓存、历史链接存在限制，不等同于紧急撤销。

## 6. 安全
正式原生 App 应通过代码签名结构与内容完整性校验；官方 Ed25519 签名清单决定资产信任。Developer ID 与公证可选；发布签名与 App 签名不可互相替代。敏感凭据使用 Keychain；禁止路径穿越、越权写入、未经授权执行命令或上传用户数据。测试签名与生产隔离。

## 7. 验收与发布
至少验证全新安装、启动、核心功能、重启、旧版更新、配置保留、失败回滚、卸载、不兼容环境和非法包拒绝、其他插件不受影响。复合插件额外验证组件通信和版本一致性。使用隔离环境，完成后由授权开发者确认发布。

## 8. 交付清单
源码工程、构建打包脚本、标准 ZIP、Manifest、图标简介、更新说明、测试结果、简短使用说明。开发行为遵循根目录 AGENTS.md。

本规范中的系统版本、处理器架构、依赖声明和跨插件冲突保护是目标约束，当前协议尚无对应的完整字段或保证。原生复合插件已接入隔离验收；真实下载后的首次启动及系统提示仍须实际验收。Chrome 解包扩展首次需用户手动加载，后续更新沿用目录；包含符号链接的 ZIP 当前被拒绝。
