# ordina 1.10.0 发布准备（2026-11-27）

**尚不可发布。** 策略为 ad-hoc App 签名、官方 Ed25519 签名清单与独立生产授权；不要求 Developer ID 或公证。真实升级、回滚及首次启动按用户要求未追加隔离测试，均未验证。

## 实际状态

- 已修复生产后端对 Registry 任何变更一律拒绝的问题。仅允许官方目标插件的变更，要求 Registry 与来源元数据、固定公钥验签的插件清单及事务资产逐项一致；其他插件、仓库、下载地址及版本约束仍受保护。专项回归：生产后端 9 项、生产写入保护 13 项、工具发布 9 项均通过。
- 使用实际 `ProductionBackend` 和只读 GitHub 状态执行三个通道六阶段 dry-run。真实线上签名、转换及历史资产检查通过；未上传的新资产由字节相同的本地文件替代，上传、远端写入及上线复核为内存模拟，不能作为实际线上上传成功的证明。
- 官方主仓库的 GitHub 写权限与可信签名能力只读检查通过；插件发布权限未确认：生产工具报告钥匙串缺少 `ordina-dev-publisher` 开发者授权。不得以本地认证或模拟状态替代。
- 修复改变发布工具内容，已生成、官方签名并验签新候选 1.8.0；原 1.6.0、1.7.0 候选和所有 App、插件资产保留。工具摘要和签名清单一致；`check_dev_tool_versions.py` 的 `acceptance_reports` 未通过，因为已有报告针对 1.6.0，按要求未追加隔离测试，不能标为通过。

## 版本兼容与发布顺序

1. 先发布工具，再发布插件，最后发布软件资产和清单；真实客户端验证完成后才发布 appcast。软件 appcast 仍保留 1.9.6、1.9.5 和 1.9.4 历史条目。
2. 1.9.5／1.9.6 源码忽略 `minClientVersion`，因此不能依赖该字段。妙记 0.4.0 资产为 32,979,280 字节、45 个文件，而这些旧版客户端分别限制资产 4,000,000 字节、最多 32 个文件，当前候选无法被其安装；旧版可能显示更新失败。1.9.4 及更早的兼容清单仍引用 0.2.0。此结论针对当前精确候选，不代表未来所有原生插件均自动安全。
3. 不删除旧资产。真实下载、首次启动、升级和回滚尚未验证；没有实测不能声称可回滚或已就绪。

## 发布前仍需处理

- 在本机配置合法的官方 `ordina-dev-publisher` 签名授权，并重新只读核验插件仓库权限；不在聊天中提交凭据或私钥。
- 处理 1.8.0 旧验收报告的问题；用户要求不追加隔离测试，因此当前明确标记未通过。正式发布前须满足发布事务自身的检查，不得伪造或跳过。
- 用户明确决定如何处置尚未执行的真实升级、回滚和首次启动验证，再另行授权线上发布。
