# 开发者本机认证

开发者中心使用 RFC 6238 六位、30 秒 TOTP。重新绑定和撤销前需要 macOS 本机账户密码或 Touch ID；随后发布工具验证签名授权、官方仓库的 GitHub 写入权限和与官方公钥匹配的签名能力；隔离验收使用独立的实验室授权和签名密钥。首次绑定也会核验发布权限。密钥及已使用计数器存储在本机 Keychain；会话仅存在进程内，最长 30 分钟。撤销认证不删除发布事务。

TOTP 只保护本机交互，修改客户端或直接调用工具可以绕过此界面。Python 发布引擎仍独立验证仓库授权及可信签名，GitHub 服务端授权和客户端签名验证是生产边界。隔离模式不能用于生产发布。生产发布工具 1.2.0 候选清单尚未正式签名或发布。

本机身份验证依赖 macOS 账户安全，并不是邮箱验证或远程身份认证；能够控制本机账户和官方发布凭据的人仍可重新配置认证。

## 新设备与迁移

每台 Mac 独立配置：先安装经官方签名清单验证的发布工具，再通过受控方式配置该开发者的官方签名授权、GitHub CLI 登录与仓库写入权限，以及与官方公钥匹配的发布签名能力。正式凭据应通过组织已有的安全方式分别配置，不能放入 App、公开包、日志或验收环境；不复制其他设备的 TOTP 密钥。工具和签名能力必须在目标 Mac 实际可用，无法核实时拒绝绑定。然后在新设备生成独立二维码并用手机绑定；它不会同步或覆盖旧设备的绑定。每台 Mac 的会话和重放记录独立，macOS Keychain 条目不启用同步。

更换手机时，在要恢复的 Mac 上选择“无法访问身份验证器？”，通过该 Mac 的 Touch ID 或账户密码，再核验官方发布权限；使用新手机扫描新二维码并输入验证码。成功保存新绑定之前原绑定保持有效；取消、验证失败或写入失败不应撤销原绑定。逐台迁移其他 Mac，确认完成后再从旧手机移除对应条目。隔离验收使用独立测试凭据和测试钥匙串，不证明生产凭据已配置。
