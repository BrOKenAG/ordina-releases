# 原生复合插件（协议 2）

`macos.application` 表示包含原生 App；最低客户端版本为 1.10.0。ZIP 根目录包含 `plugin.json`，由 `files` 明确列出 App 的 `Example.app/Contents/…` 文件并标为 `application`，可执行文件标记 `executable: true`。Resolve 入口、引擎、扩展及 Native Messaging Host 继续使用既有角色和固定安装目录。用户安装时不运行 ZIP 中的安装脚本。

安装器核对签名清单和所有文件摘要，先在隔离暂存区重建 App，再验证代码签名、Developer ID 和公证结果。仅 Debug 隔离环境可使用临时 ad-hoc 测试签名；正式版本没有该例外。安装、更新和卸载复用统一文件事务，失败时恢复已修改文件；用户修改的文件保留。支持的 App 文件必须是普通文件，包含符号链接的 ZIP 会被拒绝；插件发布者须提供签名有效且不依赖符号链接的包。

Python 引擎所需的解释器及依赖必须由发布者一同打包，并由插件自身使用相对路径定位，不能依赖用户安装 Python；ordina 不执行开发者提供的安装命令，也不会自动下载解释器。应用运行时可用性仍取决于插件包本身，隔离占位样例只测试组件安装，不提供实际业务功能。

旧客户端的公共 Registry 不包含新能力名，避免未知字段使整个目录失效；完整能力保留在签名插件清单中。旧客户端可能在该插件条目显示清单无法读取；不会因此拒绝整个目录，也不能安装原生插件。已安装的传统 Python 插件不变。

Chrome 扩展文件由 ordina 安装到插件目录，首次仍需用户按界面提示在 Chrome 中加载一次解包扩展；后续更新沿用同一目录。这是已确认的浏览器分发限制，不表示 Chrome 扩展能够静默一键启用。正式发布工具 1.4.0 仍为未签名候选，生产 Developer ID 和公证的真实端到端验证尚需有效的正式签名产物。
